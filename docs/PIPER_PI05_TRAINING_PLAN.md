# Piper 的 π0.5 微调路线

> 路线更新：2026-10-14。用户转述学长要求使用 π0.5 训练机械臂，硬件采用固件直连。
> 本文以 Physical Intelligence 的 π0.5 为模型目标，训练实现暂以官方 openpi 为参考；
> 用户暂不知道学长使用的训练仓库，项目先按官方 openpi 组织数据适配，不以此阻塞只读数据准备。
> 后续安装训练环境前再固定版本和配置。目标仍为香蕉入盒，之后再考虑叠盒。
> 当前仍不发送真实 CAN 控制帧，不推进右侧真实运动。

## 1. 纠正原先的检测器路线

之前的 A2 将目标拆成香蕉/纸盒检测与 LabelMe 标注。π0.5 是视觉语言动作模型，官方微调示例
使用图像、机器人状态、动作与任务文本，不要求物体框或多边形。因此停止新增 LabelMe 标注，
不将 YOLO 检测器、COCO 转换或盒口定位作为 π0.5 微调的必经步骤。已有标注及图像保留。

固件直连是一种人工主从操作方式；人拖动主臂让从臂执行任务仍可用于采集示教数据。
“不使用上位机示教桥”不等于“不需要人工动作示范”。

## 2. 当前材料的用途

2026-10-14 对 `can_left` 做过一次 3 秒只读普查：收到 `9120` 帧、`20` 个常规核心反馈 ID，
关节和夹爪反馈齐全，未发现偏移反馈或 `0x151/0x155~0x157/0x159` 动作目标帧。
这仅说明该采样窗口的观测结果，不能证明直连配置失效，也不能确认反馈的实体来源。
下一步先确认切换后的物理接线与动作目标是否进入电脑监听的总线，不为获取数据主动拖动主臂。

用户随后确认电脑仍接在左侧主从共用总线。再次 5 秒只读采样收到 `15200` 帧，只观察到
常规反馈 ID，动作目标帧和 `0x2B*`、`0x2C*` 均未出现。不能根据常规反馈断定两台臂均上电、
也不能将反馈直接标为从臂状态。用户确认左主臂电源指示灯亮，采样时无人移动主臂；
静止窗口没有动作帧不足以判断直连是否异常，也不证明动作帧一定只在运动时发送。
后续需核验学长配置后的直连功能及控制 ID 偏移，不主动切换模式或重新配置角色。

用户已确认学长在切换后实际验证过左侧主臂拖动、从臂跟随及夹爪开合。下一步在一次现场确认
安全的小幅左侧人工操作期间只读监听，核验动作和反馈帧的 ID、单位和时间关系。程序仍不发送
任何控制帧；不会由此启动右侧运动、上位机示教发送或自主执行。

### 直连动作观测与接收器（2026-10-14）

用户在 30 秒只读普查期间进行了已验证的小幅左侧操作，采到 `100120` 帧、`28` 个 ID。
`0x155/0x156/0x157/0x159` 各 `2105` 帧，按整个窗口平均约 `70 Hz`；这不是严格固定控制频率。
同时观察到 `0x151`、`0x190`、`0x471`、`0x476` 各 `125` 帧。只读工具没有发送它们，
仅凭接收数据也不能证明具体发送者。`0x471` 不加入动作向量，也不模仿发送。

新增 `piper_direct_dataset_reader`，纯接收、无 `--send` 选项：

```bash
# SSH 新建终端 12-直连数据只读；相机和数据流终端保持运行
cd ~/piper_tjp
source /opt/ros/humble/setup.bash
source install/setup.bash
ros2 run piper piper_direct_dataset_reader --can-port can_left
```

默认不偏移，输出以下话题：

| 话题 | 类型 | 含义 |
| --- | --- | --- |
| `/dataset/can_left/action_target` | `sensor_msgs/msg/JointState` | 观测到的六关节位置目标（rad）和夹爪目标（m） |
| `/dataset/can_left/feedback_observed` | `sensor_msgs/msg/JointState` | 总线上六关节与夹爪反馈；实体归属尚未确认 |
| `/dataset/can_left/raw_can` | `std_msgs/msg/String` | JSON 原始帧，包含 ID、载荷、SocketCAN 时间及主机接收时间 |

四个位置帧均有新数据、最老接收值不超过 `100 ms`、接收与 CAN 时间戳的帧间差不超过
`50 ms`，才拼接一个七维向量；源 CAN 时间比接收时间早或晚超过 `100 ms` 时，只保留原始帧。
完整向量用最后一个源帧时间，不周期性重复发布旧状态。拼接不是固件原子控制周期证明，
未来训练对齐需使用原始帧核验各关节的时间。缺动作帧时没有动作消息，不复制反馈冒充动作。

夹爪失能、清错失能及设零事件不输出位置动作向量，仍记录原始帧。当前 `0x159` 末次目标为
约 `-1.3 mm`，接收器原样保留有符号行程，不自行裁零；这不是安全运动目标，后续须核验零点
及训练/执行映射。原始 JSON 标注 `entity_verified=false`，ROS `frame_id` 同样标为未确认实体。
反馈未偏移不能单独确定上报者是从臂，共用总线相同 ID 可能无法区分实体，正式数据验收前必须解决。

已通过 30 项相关测试与 `piper` 编译。五秒真实只读 ROS 检查收到 `4020` 条原始帧和
`1005` 条反馈消息；当时没有动作帧。合成帧 ROS 回放分别收到 `997` 条动作与反馈消息，
验证了发布路径，但不替代真实动作话题验收。本次所有检查均未发送 CAN 控制帧。

当前用户下一项是启动接收器，检查两路七维话题；动作仍只能沿用现场已验证的小幅左侧人工操作，
不拿香蕉、不操作右侧，不将本轮检查计为正式动作训练回合。

用户随后通过 ROS `echo` 实际收到两路七维消息：反馈夹爪 `-0.0007 m`，动作夹爪
`-0.0013 m`；六关节均按 rad 输出。两次取样时间分别为 `1791977744` 和 `1791978257` 秒，
相隔约 8 分半，不能据此计算同一时刻的跟随误差。真实动作发布路径已确认，实体归属仍未确认。
用户要求停止重复空载测试，后续改为录制一条完整人工入盒演示，同时离线检查数据。
首条候选演示将相机流切为已验证的 `5 Hz`，只录三路 RGB、两路直连观测、原始 CAN 和标签；
最终训练/执行节拍另行固定。详细终端与录制命令见[固件直连演示采集](PIPER_DIRECT_DEMONSTRATION.md)。

原定 `format_checks/direct-left-001` 空载格式试录取消，不再要求用户执行。
校验器新增 `--mode direct_demonstration`，使用三路 RGB 和直连目标/反馈/原始帧话题，
要求开始、结果、结束标签齐全；旧 `demonstration` 仍用于历史上位机方案。
新增离线 `piper_direct_dataset_prepare`，导出 JPEG、七维状态/动作 NPZ、源时间戳及质量清单。
保留 `training_ready=false`，待实体归属、夹爪零点和具体模型适配确认后再导入 LeRobot/openpi。

- `scene-a01` 至 `scene-a04` 的静态包验证相机、目录与回合标签，未包含完整入盒动作。
- 4 张 LabelMe 标注保留为历史视觉检查资料；`scene-a04` 不再要求人工标注。
- 相机启动、图像压缩、录包和回合标签工具可继续使用。
- 上位机示教模式下验证过的关节/夹爪话题，不能未经核验直接当作当前直连数据源。
- `static` 校验通过不代表数据满足 π0.5 动作训练要求。

## 3. 一条训练样本需要什么

### 首条成功候选演示（2026-10-14）

用户首次尝试耗时较久，保留原包后换回合编号重新采集。`banana-direct-a05-002` 时长
`114.71s`、`85.2 MiB`，七路齐全，消息总数 `142633`；三路 RGB 各 `537/569/569` 帧，
动作 `4895`、反馈 `22942`、原始 CAN `113112`、标签 `9`。`direct_demonstration`
结构校验通过，`start/success/end` 各三条。用户确认成功，抽查第三视角可见完整流程的
盒外初态、机械臂接近夹取和盒内终态；这不是逐帧成功检测。

开始至成功标签为约 `49.04s`；目标消息覆盖该窗口相对 `11.41~45.65s`。
候选输出保存在 `data/2026-10-14/banana_into_box/scene-a05/banana-direct-a05-002-candidate/`，
包含 `139` 个对齐样本和三路 JPEG，状态/动作均为 `139×7`。有效频率 `4.05 Hz`，
最大内部间隙 `1.235s`；严格 `format_valid=false`，仍保持 `training_ready=false`。

进一步读取原包：反馈相邻消息最大间隔约 `6.49 ms`；动作相邻消息最大间隔约 `1.065s`，
第三视角图像在该任务窗口出现约 `1.235s` 的间隔。候选内部缺口包含相机真实间隔和对齐
舍弃，不通过放宽阈值或伪造动作把它标为合格。暂不据此断言相机硬件、USB 或压缩节点的根因。
本轮保留成功演示和所有原始数据，先离线定位缺口及整理适配，不要求立即重录或重新做空载测试。

进一步软件整理已生成 `banana-direct-a05-002-candidate-v2/`，139 个样本在每个缺失的
5 Hz 网格点处切为 17 段，长度为 `9,2,1,1,4,8,1,24,11,5,5,3,3,17,10,4,31`。
动作序列长度 `5/10/25/50` 的完整窗口数分别为 `84/48/7/0`；不得跨段拼接或把段落均称为成功回合。
[官方模型配置](https://github.com/Physical-Intelligence/openpi/blob/main/src/openpi/models/pi0_config.py)
默认 `action_horizon=50`，因此目前没有满足该默认长度的完整窗口；不自行改短长度掩盖采集缺口。
v2 仍是候选中间格式，尚未导入 LeRobot/openpi。

相机压缩节点已增加可选 `enable_depth=false`，RGB 输出改为可靠传输、队列 30，单流编码/发布
锁覆盖完整发布过程，并防止源时间倒退。相机输入保留 best-effort，既有静态六路模式仍默认可用。
独立 ROS 域的合成输入验证三路各 15 条输出、深度关闭；尚未在新的真实演示中验证改善程度。
现有包不能确定空档发生于采样、DDS 投递还是录制，软件改进不等于根因已确诊。

| 内容 | Piper 数据来源与待核验项 |
| --- | --- |
| 图像 | 选定第三视角及夹爪 RGB 相机，保留采集时间戳；视角映射训练和推理一致 |
| 状态 | 从臂实际六关节角度和夹爪行程；确认反馈 ID、实体归属、单位、顺序及新鲜度 |
| 动作 | 固件主臂实际发送给从臂的控制目标；只读监听，确认目标含义、单位与夹爪状态 |
| 任务文本 | 明确的语言指令，例如“把香蕉放入纸盒”，转换时映射到模型任务提示 |
| 回合信息 | 开始、结果、结束和场景编号；保存完整连续动作及成功/失败信息 |

动作目标与从臂实测状态须分别保存。不能直接把同一时刻的从臂反馈复制成动作，也不能
未经协议核验就将主臂角度视为下发目标。若选择未来状态作为动作标签，必须先定义时间偏移
及转换规则，并验证其与推理时的动作执行接口一致。

RGB 是官方示例的图像输入；深度图可保留作排障或辅助信息，是否输入模型由适配配置决定。
静态采集的 `2 Hz` 不直接作为动作训练频率。动作采集频率、相机频率及对齐误差须根据所选
训练实现和动作执行节拍确定；不能用插值凭空补出没有录到的视觉变化。

## 4. 接下来的顺序

2026-10-14 收尾：用户今天未在终端 07 粘贴新版 RGB-only 命令。软件改进与 49 项相关测试、
编译已完成，真实效果待下一条正常任务演示验证；不因跨天恢复而重复空载测试。
Git 保存代码和文档，演示原包及候选只在本机 `data/`。明天先恢复文档、Git 和进程状态，再续接以下工作。

1. 暂以官方 openpi 和 π0.5 基础模型为参考，先准备左侧状态/动作数据；不预先假定 Piper
   适配现成 ALOHA/DROID 权重或双臂维度。训练环境安装前固定具体版本和配置。
2. 对当前固件直连只读监听，确认状态和动作可分辨；不要求用户为了此检查移动机械臂。
3. 建立带原始时间戳的状态/动作记录与图像对齐，先验收完整数据格式和数据新鲜度。
4. 现场确认直连跟随、夹爪和停止流程后，另行安排人工完成抓取、运输、放入、松开的演示采集。
5. 将完整回合转换为训练实现支持的 LeRobot 格式，固定字段、单位、动作表示和相机映射，
   按独立布置划分训练及评测数据，再计算状态/动作归一化统计。
6. 微调 π0.5 并先做离线加载/推理检查；模型动作输出经限位、速度和失联保护验证后，
   才安排左侧受控自主入盒。固件直连与模型发送不能同时作为动作控制来源。

几何标定不是所有端到端 π0.5 微调方案的硬性前置步骤；若执行器使用笛卡尔目标或几何保护，
仍应为该接口明确坐标系和标定要求。当前不承诺训练成功率或固定所需回合数。

驱动 `595.99.02`。官方 openpi README 的单 GPU 估计为推理 `>8 GB`、LoRA 微调 `>22.5 GB`、
全参数微调 `>70 GB`；具体支持取决于 JAX/PyTorch 实现、版本和配置，不能仅据显存保证可训练。
